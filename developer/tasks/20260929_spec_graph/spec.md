# Генератор графа: спецификация

Статус: черновик.

Пометки:

- `[принято]`: правило подтверждено.
- `[предложение]`: правило предложено, ждёт решения.
- `[?]`: вопрос открыт. Номер вопроса ведёт в раздел «Открытые вопросы».

## 1. Назначение и границы

Генератор получает абстрактную модель графа и возвращает SVG.

- Генератор не знает о StrictDoc. Адаптер StrictDoc строит модель отдельно.
- Генератор детерминирован: одинаковый вход даёт побайтно одинаковый SVG.
- Все решения о раскладке генератор принимает до сериализации SVG.
  Сериализатор не меняет геометрию.
- Решения о раскладке не зависят от CSS: толщины линий, цветов, шрифтов в
  стилях.

## 2. Термины

| Термин | Значение |
|---|---|
| Нода | Прямоугольник с заголовком и данными. |
| Композитная нода | Нода, которая содержит другие ноды. Имеет свои данные, заголовок, ссылку и связи. |
| Контейнер | Корень графа или композитная нода. Контейнер раскладывает своих непосредственных детей. |
| Связь | Направленное ребро от ноды-источника к ноде-цели. Имеет тип. |
| Тип связи | Внешний идентификатор. Генератор знает только стиль, подпись и правила отображения типа. |
| Порт | Точка на стенке ноды, где связь начинается или заканчивается. |
| Проходной порт | Точка, где связь пересекает стенку композитной ноды. Не является началом или концом связи. |
| Канал | Пустое пространство между соседними нодами или между нодой и стенкой контейнера. По каналам идут связи. |
| Полоса | Одна линия внутри канала. Ширина канала определяется числом полос. |

[?1] Термины старого черновика «туннель», «шахта», «магистраль», «пучок»
пока заменены на «канал» и «полосу». Нужно решить, какие термины оставить.

## 3. Входная модель

[предложение] Модель:

```
Graph
  root: Container
  edges: list[Edge]
  relation_types: dict[type_id, RelationStyle]

Node
  id: str             # уникален в графе
  title: str
  data: ...           # [?2]
  link: str | None
  children: list[Node]   # пусто у обычной ноды

Edge
  source: node id
  target: node id
  type: type_id
```

[принято] Порядок детей контейнера задан входной моделью. Генератор не
переставляет детей.

[?3] Как порядок детей переходит в геометрию: одна колонка сверху вниз,
несколько колонок, строки?

[?4] Нужны ли группы (объединение нод без собственной ноды-заголовка), или
документы и разделы полностью покрываются композитными нодами?

Нормализация входа:

- Точные дубликаты связей (тот же источник, цель и тип) рисуются один раз.
  Генератор сообщает о дубликате в диагностике.
- Связи с одинаковыми концами, но разными типами, остаются отдельными
  параллельными линиями.
- [?5] Связь ноды с самой собой.
- [?6] Связь между предком и потомком: ребёнок связан со своей композитной
  нодой, или композитная нода со своим ребёнком.

## 4. Результат

[предложение] Генератор возвращает:

- SVG-строку
- диагностику: список проблем с идентификаторами нод и связей
- [?7] отдельную структуру для интерактивности, или только атрибуты в SVG.

## 5. Инварианты результата

Инварианты проверяются тестами на любом входе.

- Ноды не перекрываются.
- Рамка композитной ноды содержит всех её непосредственных детей.
- Все сегменты связей ортогональны.
- Связь не проходит через ноду, заголовок или рамку, кроме своих портов и
  проходных портов.
- Связь не пересекает саму себя и не образует петель.
- Две связи не делят общий сегмент.
- Две связи не касаются друг друга в точках поворота. Т-образные
  соединения запрещены.
- Две связи пересекаются только перпендикулярно, внутри прямых сегментов
  обеих связей.
- Один порт принадлежит одной связи.
- Все линии и наконечники находятся внутри области SVG.
- Порядок детей каждого контейнера совпадает с порядком во входе.

## 6. Этапы алгоритма

[предложение] Генератор работает этапами. Каждый этап:

- получает результат предыдущего этапа
- возвращает неизменяемую структуру данных
- не меняет решения предыдущих этапов
- тестируется отдельно.

| № | Этап | Вход | Выход | Пиксели |
|---|---|---|---|---|
| 1 | Проверка и нормализация | Входная модель | Нормализованный граф, диагностика, циклы | нет |
| 2 | Структура | Нормализованный граф | Логическое положение детей в каждом контейнере: колонка, строка | нет |
| 3 | Топология маршрутов | Структура | Для каждой связи: последовательность каналов, стенок и сторон портов | нет |
| 4 | Назначение полос | Топология | Номер полосы каждой связи в каждом канале. Порядок портов на стенках | нет |
| 5 | Размеры (изнутри наружу) | Структура, полосы, размеры текста | Размер каждой ноды, ширина каждого канала, размер каждого контейнера | да |
| 6 | Координаты (снаружи внутрь) | Размеры | Абсолютные координаты нод, каналов, портов | да |
| 7 | Геометрия связей | Координаты, полосы | Ломаные линии связей | да |
| 8 | Сериализация | Всё выше | SVG | да |

Этапы с 1 по 4 не используют пиксели. Ширина канала на этапе 5 следует из числа
полос на этапе 4. Этап 7 только переводит полосы в координаты. Этап 7 не
ищет маршруты.

[?8] Нужен ли корректирующий проход после этапа 7? Старый черновик его
допускал. Предложение: не допускать. Если геометрия не сходится, ошибка
находится в этапах со 2 по 4.

## 7. Раскладка детей контейнера

[?3] Правила зависят от ответа на вопрос о порядке.

Из старого черновика, не подтверждено:

- Связи задают уровни и ветви графа.
- Прямая основная ветвь остаётся в одной колонке.
- Ноды без связей располагаются отдельным компактным блоком.
- Композитный ребёнок занимает в раскладке родителя место одной ноды
  переменного размера.
- Внутренняя сетка композитной ноды не зависит от сетки родителя.

## 8. Композитные ноды

Из старого черновика, не подтверждено:

- Заголовок входит в композитную ноду. Заголовок кликабелен.
- Заголовок и его отступы являются препятствием для связей.
- Связь ребёнка со своей композитной нодой заканчивается на заголовке
  изнутри [?6].
- Собственная связь композитной ноды начинается или заканчивается на её
  рамке снаружи.
- Внешняя связь с композитной нодой не заходит внутрь неё.
- Связь внутренней ноды с внешней пересекает стенку в проходном порту.
- На промежуточных уровнях вложенности связь сохраняет координату.

## 9. Каналы и полосы

Из старого черновика, не подтверждено:

- Одна полоса входит в базовую ширину канала и не раздвигает сетку.
- Каждая следующая полоса расширяет только свой канал.
- Освободившаяся полоса используется повторно, если это не блокирует
  другие связи.
- Номер полосы сохраняется на повороте.
- Соседние линии поворачивают вместе, без смены порядка.
- Связи одного источника идут соседними полосами.

### Правостороннее движение

Из старого черновика, не подтверждено:

- Горизонтальный канал: вправо в нижней половине, влево в верхней.
- Вертикальный канал: вверх справа, вниз слева.
- Разделительная полоса нужна только при встречном движении.
- Связь, которая покидает канал раньше, получает полосу ближе к стороне
  съезда.

## 10. Порты

Из старого черновика, не подтверждено:

- Вертикальная связь без смещения использует центральный порт.
- Боковые порты занимают свою половину стенки.
- Порядок портов следует порядку полос.
- Входящие и исходящие порты на одной стенке получают разные позиции на
  регулярной сетке.
- Порты композитной ноды находятся только на её стенках.

[?10] Какие стороны ноды используются для портов: только верх и низ, или

## 13. Диагностика и debug-слой

Из старого черновика, не подтверждено:

- Генератор находит компоненты сильной связности и циклы на уровне модели.
- SVG выделяет участников цикла и циклические связи.
- Debug-слой показывает каналы, полосы, направления и проходные порты.
- Debug-слой строится из тех же данных, что и основной SVG.

## 14. SVG

Из старого черновика, не подтверждено:

- Наконечники стрелок рисуются поверх рамок.
- Зона hover и focus линии шире видимой линии.
- Hover и focus не увеличивают наконечник.
- Размер SVG учитывает линии, наконечники и внешние каналы.
- Внешние отступы считаются отдельно для каждой стороны.
