# Restrict Clone to regular document nodes

## WHAT

StrictDoc shall support Clone only for regular, non-composite document nodes.
StrictDoc shall not support Clone for sections or other composite nodes.

In this task, a regular node means an `SDocNode` with
`is_composite == False`. The rule includes `REQUIREMENT`, `TEXT`, and
non-composite custom grammar nodes. The rule excludes `SECTION` and composite
custom grammar nodes.

The implementation shall enforce the same rule in the UI and the server:

- show the Clone control only for supported regular nodes
- keep the existing enabled and disabled states for supported regular nodes
- omit both Clone controls for sections and other composite nodes
- reject a direct Clone request for an unsupported node with HTTP 403
- preserve cloning for eligible regular nodes.

Do not use `get_type_string()` to decide whether a node supports Clone. The
method returns the legacy UI category `requirement` for every `SDocNode`,
including sections.

## WHY

The original e2e test tried to verify that a section had no Clone control. The
test used `data-testid="node-section"` to select the section. A regular
`SECTION` node renders as `data-testid="node-requirement"`, so the selector
matched no node. The negative descendant assertion passed although the test
had not established that the section existed.

The same category mismatch exposed a functional gap. The template displays
Clone for every `SDocNode`. The server also accepts every deletable `SDocNode`.
As a result, StrictDoc currently clones sections even though the product rule
limits Clone to regular nodes.

The UI check alone cannot enforce the rule. A client can call the Clone route
directly. The server must reject unsupported nodes before it creates the clone
form.

## Implementation requirements

### Clone support and permissions

Separate operation support from per-node permissions.

Add a predicate that reports whether the node kind supports Clone. The
predicate shall return true only for non-composite `SDocNode` instances.

Keep `can_clone_node()` responsible for permissions and node state. The method
shall return false when:

- the node kind does not support Clone
- the document or node state prevents deletion and cloning.

The node-controls template shall:

- omit the Clone control when the node kind does not support Clone
- render the enabled control when `can_clone_node()` returns true
- render the disabled control when a supported regular node fails the
  permission check.

### Route enforcement

The `/actions/document/clone_requirement` route shall reject sections and
other composite nodes with HTTP 403. The error shall state that the node kind
does not support cloning.

The route shall keep the existing permission check for supported regular
nodes. Autogenerated or otherwise protected regular nodes shall remain
forbidden.

### Stable grammar-type selector

Add a stable HTML attribute that exposes the grammar type of an `SDocNode`.
For example:

```html
<sdoc-node data-node-type="SECTION">
```

Do not replace the existing `data-testid="node-requirement"` category in this
task. Several tests use that category for all regular content nodes.

Use the grammar-type attribute to select a regular `SECTION` node in tests.
The test shall establish that the section exists before control assertions.

Do not use the existing `Section` page object for this assertion. The current
page object selects `data-testid="node-section"`, which represents an
included-document root after the legacy section-model migration.

### Tests

Add or update tests that prove:

- an eligible regular node displays Clone and the user can clone it
- a regular `SECTION` node exists in the fixture
- the section renders neither `node-clone-action` nor
  `node-clone-action-disabled`
- a direct Clone request for the section returns HTTP 403
- a protected regular node still renders the disabled Clone control
- the existing custom prefix and custom UID clone scenarios still pass.

The negative UI assertion shall use a previously verified section selector.
The test shall not pass when the parent selector matches no node.

### Documentation

Update `SDOC-SRS-161` in
`docs/strictdoc_21_l2_high_level_requirements.sdoc`. The requirement shall
state that Clone applies to regular, non-composite document nodes.

Add an Unreleased release note. The note shall state that StrictDoc no longer
offers or accepts Clone for sections and other composite nodes.

## Out of scope

The investigation found broader naming debt:

- `get_type_string()` returns legacy UI and route categories, not grammar
  types
- the category `section` represents an included-document root
- the category `requirement` represents every `SDocNode`
- the e2e `Section` page object currently represents an included-document
  root
- the Clone route and form classes use `requirement` in names although they
  also serve `TEXT` and custom regular nodes.

Do not rename these shared APIs in this task. Record the naming problem in the
archived investigation and handle the refactoring separately.
