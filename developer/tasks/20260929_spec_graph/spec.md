# Генератор графа: спецификация

Статус: черновик.

Пометки:

- Без пометки: правило принято.
- `[предложение]`: правило предложено, ждёт решения.
- `[?N]`: вопрос открыт. Номер ведёт в раздел «Открытые вопросы».
- `[отложено]`: не входит в первую реализацию.

## 1. Назначение и границы

Генератор получает абстрактную модель графа и возвращает SVG.

- Генератор не знает о StrictDoc. Адаптер StrictDoc строит модель отдельно.
- Генератор детерминирован: одинаковый вход даёт побайтно одинаковый SVG.
- Все решения о раскладке генератор принимает до сериализации SVG.
  Сериализатор не меняет геометрию.
- Решения о раскладке не зависят от CSS: толщины линий, цветов, шрифтов в
  стилях.
- JavaScript интерактивности и CSS-стили находятся в отдельных файлах, а
  не в Python-коде.
- Граф может содержать тысячи нод.

## 2. Термины

| Термин | Значение |
|---|---|
| Нода | Прямоугольник с заголовком и данными. |
| Композитная нода | Нода, которая содержит другие ноды. Имеет свои данные, заголовок, ссылку и связи. |
| Группа | Рамка вокруг зоны размещения нод, с подписью. Не является нодой: не кликабельна, не имеет связей. Влияет только на раскладку. |
| Контейнер | Корень графа, композитная нода или группа. Контейнер раскладывает своих непосредственных детей. |
| Связь | Направленное ребро от ноды-источника к ноде-цели. Имеет тип. Стрелка стоит у цели. |
| Тип связи | Внешний идентификатор. Генератор знает только стиль, подпись и правила отображения типа. |
| Грань | Сторона прямоугольника ноды или контейнера: верхняя, нижняя, левая, правая. |
| Порт | Точка на грани ноды или на линии заголовка контейнера, где связь начинается или заканчивается. |
| Проходной порт | Точка на боковой грани композитной ноды, где связь пересекает рамку. Не является началом или концом связи. |
| Канал | Пустое пространство между соседними нодами, между нодами и рамкой контейнера, между рамками. По каналам идут связи. |
| Полоса | Одна линия внутри канала. Ширина канала определяется числом полос. |
| Пучок | Связи одного источника, которые идут в одну сторону. |
| Одиночная нода | Нода без связей. |
| Локальный корень | Нода группы, которая является корнем при раскладке внутри группы. |

## 3. Режимы раскладки

Генератор поддерживает режимы раскладки. Режимы не совмещаются в одном
графе.

| Режим | Контейнеры | Положение нод задают | Использование в StrictDoc |
|---|---|---|---|
| Уровни | Нет | Связи | Вид «документы» без папок |
| Уровни с группами | Группы | Связи и принадлежность к группе | Вид «документы» с папками. Вид «ноды» с тегами |
| Структура | Композитные ноды | Порядок детей во входе | Вид «ноды» со структурой документов |

- В режиме «структура» связи не влияют на положение нод внутри
  контейнера. Связи влияют на ширину каналов.
- В режимах «уровни» и «уровни с группами» порядок нод во входе влияет на
  порядок колонок.

## 4. Входная модель

```
Graph
  mode: Mode
  root: list[Node]           # дети корня, по порядку
  groups: list[Group]        # только в режиме «уровни с группами»
  edges: list[Edge]
  relation_types: dict[type_id, RelationStyle]

Node
  id: str                    # уникален в графе
  title: str
  link: str | None
  details: list[(label, value)]  # например UID, MID, документ
  children: list[Node]       # только в режиме «структура»
  group_id: str | None       # только в режиме «уровни с группами»

Group
  id: str
  title: str

Edge
  source: node id
  target: node id
  type: type_id
```

- Генератор не интерпретирует `details`. Генератор передаёт `details` в
  SVG для интерактивности.
- Порядок детей контейнера задан входной моделью. Генератор не
  переставляет детей.
- Нода входит не больше чем в одну группу. Группа задаёт место на
  плоскости, а не логическую принадлежность.
- [отложено] Вложенные группы. Модель должна допускать их добавление.

### Нормализация

- Точные дубликаты связей (тот же источник, цель и тип) рисуются один
  раз. Генератор сообщает о дубликате в диагностике.
- Связи с одинаковыми концами, но разными типами, остаются отдельными
  параллельными линиями.
- Связь ноды с самой собой не рисуется. Нода получает значок ошибки
  (раздел 13).
- [предложение] Каждая связь после нормализации получает идентификатор
  `edge-N`, где N: номер связи в порядке входа, без дубликатов и связей
  ноды с самой собой.

### Ошибки входа

Ошибки входа являются нарушением контракта модели кодом, который строит
модель. Проблемы в данных пользователя не являются ошибками входа.

Генератор отклоняет вход целиком при следующих ошибках:

- две ноды с одинаковым идентификатором
- связь с неизвестной нодой
- дети у ноды вне режима «структура»
- группа у ноды или список групп вне режима «уровни с группами»
- ссылка на неизвестную группу
- две группы с одинаковым идентификатором.

Остальные проблемы входа генератор показывает в диагностике.

При ошибке входа генератор выбрасывает исключение `GraphModelError` с
текстом ошибки. Генератор не строит SVG.

Экран фичи ловит `GraphModelError`. Экран показывает текст ошибки вместо
графа и пишет ошибку в лог. Остальной экспорт продолжается.

Стили типов связей (`relation_types` в модели) добавляются в
модель вместе с этапом сериализации.

## 5. Результат

Генератор возвращает:

- SVG-строку
- диагностику: список проблем с идентификаторами нод и связей.

Данные для интерактивности генератор записывает в `data-*`-атрибуты
элементов SVG: идентификаторы, концы связей, `details`. При загрузке
страницы JavaScript читает атрибуты и строит индекс соседей: для каждой
ноды список её связей. Генератор не выдаёт отдельный JSON с этими
данными.

## 6. Инварианты результата

Тесты проверяют инварианты на любом входе.

- Ноды не перекрываются.
- Рамка контейнера содержит всех его непосредственных детей.
- Все сегменты связей ортогональны.
- Связь не проходит через ноду, заголовок композитной ноды или рамку
  композитной ноды, кроме своих портов и проходных портов.
- Рамка и подпись группы не являются препятствием для связей.
- Связь не пересекает саму себя и не образует петель.
- Две связи не делят общий сегмент.
- Две связи не касаются друг друга в точках поворота. Т-образные
  соединения запрещены.
- Две связи пересекаются только перпендикулярно, внутри прямых сегментов
  обеих связей.
- Один порт принадлежит одной связи.
- Все линии и наконечники находятся внутри области SVG.
- В режиме «структура» порядок детей каждого контейнера совпадает с
  порядком во входе.

## 7. Этапы алгоритма

Генератор работает этапами. Каждый этап:

- получает результат предыдущего этапа
- возвращает неизменяемую структуру данных
- не меняет решения предыдущих этапов
- тестируется отдельно.

| № | Этап | Вход | Выход | Пиксели |
|---|---|---|---|---|
| 1 | Проверка и нормализация | Входная модель | Нормализованный граф, диагностика, циклы | нет |
| 2 | Структура | Нормализованный граф | Логическое положение детей в каждом контейнере: колонка, строка | нет |
| 3 | Топология маршрутов | Структура | Для каждой связи: последовательность каналов, граней и портов | нет |
| 4 | Назначение полос | Топология | Номер полосы каждой связи в каждом канале. Порядок портов на гранях | нет |
| 5 | Размеры (изнутри наружу) | Структура, полосы | Размер каждой ноды, ширина каждого канала, размер каждого контейнера | да |
| 6 | Координаты (снаружи внутрь) | Размеры | Абсолютные координаты нод, каналов, портов | да |
| 7 | Геометрия связей | Координаты, полосы | Ломаные линии связей | да |
| 8 | Сериализация | Всё выше | SVG | да |

- Этапы с 1 по 4 не используют пиксели.
- Ширина канала на этапе 5 следует из числа полос на этапе 4.
- Этап 7 переводит полосы в координаты. Этап 7 не ищет маршруты.
- Корректирующего прохода после этапа 7 нет. Если геометрия не сходится,
  ошибка находится в этапах со 2 по 4.
- Сложность каждого этапа не выше O(n log n) по числу нод и связей, кроме
  поиска циклов. Галерея содержит кейс с тысячами нод для проверки
  времени.

## 8. Режим «уровни»

### Направление

Связи режима означают «ребёнок → родитель». Стрелки направлены вверх.
Граф строится сверху вниз.

### Острова

- Остров: компонента связности графа. Одиночные ноды в острова не
  входят.
- Острова упорядочены по первой ноде острова во входе.
- Алгоритм раскладывает каждый остров отдельно.
- Острова стоят слева направо. Верхний уровень всех островов общий.

Эталонный кейс галереи: «Disconnected components form separate islands».

### Уровни

Термины:

- Корень: нода без исходящих связей, но с входящими.
- Прямой родитель: родитель ровно на один уровень выше ноды.
- Связь через уровень: связь к родителю, который выше прямого уровня.
  Такая связь получает встроенный тип `warning` (раздел 15). Ситуация
  есть только в режимах «уровни» и «уровни с группами».

Алгоритм уровней:

1. Каждый корень получает верхний уровень острова.
2. Каждая другая нода получает уровень на единицу ниже самого глубокого
   из своих родителей.
3. Коррекция корня. Для корня R алгоритм рассматривает каждого ребёнка C.
   Опорные родители C: родители C, кроме R и кроме потомков R. Если у C
   есть опорные родители, кандидат для R: уровень самого глубокого
   опорного родителя C. R опускается на самый верхний из кандидатов,
   если этот уровень ниже текущего уровня R. Так R встаёт на один уровень
   выше C.
4. Если шаг 3 изменил уровень хотя бы одного корня, алгоритм повторяет
   шаги 2 и 3. Уровни только растут, поэтому повторение конечно.
5. Пустые уровни удаляются.

Скорректированный корень: корень, который шаг 3 опустил.

Эталонные кейсы галереи: «Simple chain», «Basic highway conflict»,
«Isolated document + hierarchy», «Real project case: root corrected to sit
level with its sibling», «Root correction picks the nearest child, not the
farthest».

### Колонки

Цель: цепочка нод стоит в одной колонке. Ветка: цепочка нод, в которой
каждая нода стоит под своим предпочтительным родителем.

Предпочтительный родитель ноды N. Алгоритм проверяет условия по порядку и
берёт первое выполненное:

1. У N ровно один прямой родитель. Предпочтительный родитель: этот
   прямой родитель.
2. У N ровно один родитель. Предпочтительный родитель: этот родитель.
3. У N ровно один родитель, который не является скорректированным
   корнем. Предпочтительный родитель: этот родитель.
4. Иначе у N нет предпочтительного родителя.

Алгоритм колонок. Алгоритм обходит уровни сверху вниз. Внутри уровня
алгоритм обходит ноды в порядке входа.

1. Нода с предпочтительным родителем занимает колонку этого родителя.
   Если колонку хотят занять несколько нод, колонку получает нода, которая
   раньше во входе.
2. Нода без колонки с шага 1, у которой есть прямые родители, занимает
   первую свободную колонку среди колонок прямых родителей. Родители
   перебираются в порядке входа.
3. Нода, которая проиграла спор за колонку на шаге 1, встаёт в колонку
   справа от последнего размещённого претендента на ту же колонку:
   победителя или предыдущего проигравшего. Если эта колонка занята,
   алгоритм вставляет новую колонку. Колонки правее вставки сдвигаются на
   всех уровнях. Так претенденты на одну колонку сохраняют порядок
   входа.
4. Остальные ноды занимают самые левые свободные колонки.

Шаги 3 и 4 выполняются одним проходом по нодам уровня в порядке входа.

Размещение скорректированного корня. После раскладки всех уровней
алгоритм обходит скорректированные корни в порядке входа.

1. Дети корня: дети ровно на один уровень ниже корня.
2. Целевая колонка: колонка справа от среднего ребёнка. При чётном числе
   детей средний ребёнок: левый из двух средних. Так корень с двумя
   детьми встаёт между ними, а корень с тремя детьми встаёт справа от
   среднего.
3. Ноды уровня корня в целевой колонке и правее сдвигаются вправо на одну
   колонку. Каждая нода сдвигается вместе со своей веткой.

Разрешение наложений. Если после сдвигов две ноды занимают одну позицию,
ветка ноды, которая позже во входе, сдвигается целиком. Сдвиг выбирается
так, чтобы все ноды ветки попали на свободные позиции. Приоритеты: без
расширения графа, затем наименьший сдвиг, затем сдвиг влево.

Эталонные кейсы галереи: «Corrected root with two non-skip children:
sits between them», «Corrected root with THREE non-skip children (odd
count)».

Правило локальное. Правило не минимизирует пересечения. Эталонный кейс
галереи для спора за колонку: «Three chains compete for one parent
column».

### Одиночные ноды

- Одиночные ноды стоят в отдельном блоке над связным графом.
- Блок является сеткой. Ширина сетки в колонках равна ширине связного
  графа.
- Если связного графа нет, сетка близка к квадрату.

Эталонный кейс галереи: «Standalone nodes wrap to the connected graph
width».

### Порты и каналы

- Порты находятся на верхней и нижней гранях нод.
- Каналы проходят между уровнями и между колонками.

### Маршруты

#### Каналы

- H(r): горизонтальный канал под строкой r. H(-1): канал над первой
  строкой.
- V(c): вертикальный канал справа от колонки c. V(-1): канал слева от
  первой колонки.
- Связь идёт только по каналам. Пустая клетка сетки не является каналом.

#### Форма маршрута

Связь вверх: источник в строке s, цель в строке t, s > t.

- Соседние уровни, s = t + 1. Линия выходит из верхней грани источника в
  H(t), идёт по H(t) до колонки цели и входит в нижнюю грань цели. Если
  порты стоят на одной вертикали, линия прямая, без горизонтального
  отрезка.
- Через уровни, s > t + 1. Линия выходит из верхней грани источника в
  H(s - 1), идёт по H(s - 1) до вертикального канала V(k), идёт вверх по
  V(k) до H(t), идёт по H(t) до колонки цели и входит в нижнюю грань цели.
- Канал V(k): ближайший к колонке цели со стороны источника. Длинный
  горизонтальный отрезок получается у источника, в H(s - 1).
- Если колонки источника и цели совпадают, V(k) = V(c - 1), слева от
  колонки. Связь вверх слева от ноды обходит ноду по часовой стрелке.
- Параметр генератора `SkipChannelChoice` позволяет сменить выбор на
  канал у источника. Эталонный кейс галереи: «Relations across levels
  from far columns».

Связь вниз (связь цикла): зеркально. Линия выходит из нижней грани
источника и входит в верхнюю грань цели.

Каждая связь имеет не больше двух горизонтальных отрезков и одного
вертикального отрезка в канале V.

#### Полосы в канале

Отрезок: часть маршрута внутри одного канала. У горизонтального отрезка
есть вход (вертикаль снизу или сверху) и выход (вертикаль вверх или
вниз).

- Отрезки разных направлений занимают разные половины канала по правилу
  правостороннего движения (раздел 11).
- Внутри половины порядок полос задают ограничения. Пример для связей
  вверх:
  - Вертикаль входа B снизу лежит в интервале A. Тогда полоса A выше
    полосы B.
  - Вертикаль выхода B вверх лежит в интервале A. Тогда полоса A ниже
    полосы B.
  - Для связей вниз правила зеркальные.
  - Каждое ограничение исключает одно пересечение.
- Для двух отрезков одного направления со сдвинутыми интервалами
  ограничения совместны. Пример: оба отрезка идут вправо, A начинается
  левее и кончается раньше B. Тогда A проходит над B, и пересечений нет.
- Для двух отрезков одного направления, где интервал B лежит внутри
  интервала A, ограничения противоречат друг другу. Пересечение
  неизбежно. Приоритет входа: A проходит так, чтобы не пересечь вертикаль
  входа B. A пересекает вертикаль выхода B, у цели.
- Параметр генератора `LaneConflictPriority` позволяет сменить выбор на
  приоритет выхода. Эталонный кейс галереи: «Nested relations in one
  channel».
- Отрезки, чьи интервалы не пересекаются, могут занимать одну полосу.
- Алгоритм: граф ограничений, разрыв противоречий по приоритету входа,
  топологический порядок, упаковка в полосы с повторным
  использованием. Сложность O(n log n) по числу отрезков в канале, кроме
  разрыва противоречий.

Для двух отрезков противоположных направлений с пересекающимися
интервалами пересечение неизбежно при любом порядке. Правило
правостороннего движения решает такой случай.

Каналы V устроены так же. Отрезки вверх занимают правую половину канала,
отрезки вниз левую.

#### Порты

Проход: две грани, которые смотрят в один горизонтальный канал в одной
колонке. Верхняя грань прохода: нижняя грань верхней ноды. Нижняя грань
прохода: верхняя грань нижней ноды.

Группы портов:

- Порты каждой грани делятся на три группы: левая группа, центр, правая
  группа. Горизонтальный отрезок связи левой группы уходит влево от
  порта, правой группы вправо.
- Прямая связь стоит в центре. В проходе не больше одной прямой связи.
- Внутри группы порядок портов совпадает с порядком точек, куда идут
  связи, если связь проходит порт вверх: источник на верхней грани или
  цель на нижней грани. Связь к самой левой точке получает самый левый
  порт.
- Если связь проходит порт вниз (источник на нижней грани или цель на
  верхней грани), порядок зеркальный. Так полосы вкладываются друг в
  друга без пересечения.

Правило общего ритма и фиктивного слота:

- Каждая грань нумерует порты группы сама. Тогда обе грани прохода
  держат один ритм: порты с одинаковым номером стоят на одной вертикали.
- Вертикаль порта верхней грани идёт от верха канала вниз до полосы
  отрезка. Вертикаль порта нижней грани идёт от низа канала вверх до
  полосы отрезка. Две вертикали на одной вертикали накладываются, если
  полоса верхнего порта ниже полосы нижнего порта.
- Половина канала каждого отрезка известна до назначения полос (правило
  правостороннего движения). Поэтому пару портов можно оценить заранее:

  | Отрезок верхнего порта | Отрезок нижнего порта | Пара |
  |---|---|---|
  | в верхней половине | в нижней половине | безопасна: вертикали не встречаются |
  | в нижней половине | в верхней половине | опасна: вертикали накладываются всегда |
  | в одной половине | в одной половине | опасна: результат зависит от полос |

- Если в группе прохода есть хотя бы одна опасная пара, обе грани
  нумеруют эту группу общим списком из двух блоков. Блок верхней грани
  стоит у центра, блок нижней грани дальше от центра. Каждая грань держит
  свои порты вместе, одним пучком, и пропускает позиции блока другой
  грани: фиктивные слоты. Порты граней не чередуются.
- Блок верхней грани стоит у центра, потому что для связей вверх
  неизбежные пересечения двух блоков тогда лежат у портов источников, а не
  у наконечников.
- Для связей вверх правая группа безопасна, левая опасна. Пример: нода U
  принимает связи справа, нода L под ней отправляет связи направо. Порты
  обеих граней держат один ритм. Если те же связи идут налево, порты U и L
  стоят двумя соседними блоками.
- Эталонные кейсы галереи: «Opposite ports in one gate», «Many ports in
  one gate», «Extreme gate, …».
- Порты одного пучка стоят рядом (раздел 11).
Шаг портов и переполнение грани:

- Шаг портов считается по списку нумерации. Грань, которая нумерует
  порты сама, использует свой шаг. Грань с малым числом портов сохраняет
  обычный шаг, даже если встречная грань плотная. Общий список двух
  граней использует один шаг для обеих граней.
- Минимальный шаг портов задаёт параметр раскладки. Наконечник
  вписывается в этот шаг: ширина основания наконечника равна минимальному
  шагу минус зазор между соседними наконечниками. Поэтому при минимальном
  шаге два наконечника не накладываются.
- Крайний порт стоит не ближе заданного отступа от угла ноды.
- Шаги переполнения, по порядку:
  1. Список не помещается в свою половину грани с обычным шагом: шаг
     списка уменьшается, но не ниже минимального.
  2. Сторона прохода не помещается в половину грани с минимальным шагом:
     центр прохода сдвигается в другую сторону на недостающую ширину.
     Обе грани прохода сдвигают центр одинаково, поэтому прямая связь
     остаётся прямой.
  3. Проходу не хватает ширины и со сдвигом центра: колонка
     расширяется. Все ноды колонки получают одну ширину.
- Эталонные кейсы галереи: «Extreme gate, …».

## 9. Режим «уровни с группами»

### Раскладка внутри группы

- Группа рисует рамку вокруг зоны размещения своих нод.
- Внутри зоны ноды раскладываются по правилам режима «уровни», как
  отдельный граф. Так ноды группы образуют одну непрерывную зону.
- Нода, чей родитель находится вне группы, является локальным корнем.
  Локальный корень стоит на верхнем уровне группы. Связь с внешним
  родителем рисуется.
- Нода вне групп стоит вне рамок групп.

### Размещение групп

Алгоритм сначала раскладывает ноды внутри каждой группы. Затем алгоритм
размещает блок группы среди остальных блоков.

- Группа выравнивается по уровню своей самой верхней связанной ноды.
- Расположение нод и групп балансируется по числу связей.
- Одиночные ноды группы стоят сеткой над связной частью группы. Ширина
  сетки равна ширине связной части. Если строк сетки получается больше,
  чем колонок + 2, сетка расширяется, пока это условие не выполнится.
  Так группа не превращается в высокую узкую колонку.

### Группы из одиночных нод

- Группа, в которой все ноды одиночные, стоит отдельно от связного графа,
  чтобы не мешать связям.
- Направление размещения таких групп настраивается. По умолчанию
  горизонтальное.
- Горизонтальное направление: группы стоят в ряд над связным графом. Ряд
  переносится по ширине связного графа. Если самая широкая группа шире
  связного графа, ряд переносится по её ширине.
- Вертикальное направление: группы стоят колонкой слева от связного
  графа.
- Внутри такой группы ноды стоят сеткой, близкой к квадрату.

Эталонный кейс галереи: «Standalone folder groups default to
horizontal».

### Подпись и рамка группы

- Подпись группы стоит в левом верхнем углу рамки.
- Подпись группы не кликабельна.
- Подпись имеет внутренний отступ 2-4 px, внешний отступ 6-8 px и
  непрозрачный фон.
- Связи проходят под подписью и пересекают рамку группы свободно.

Эталонные кейсы галереи: «Complex groups with an externally anchored
member», «Standalone folder groups default to horizontal», «Group
boundaries reserve routing space», «Group container with external
relations».

## 10. Режим «структура»

### Направление

Стрелка указывает на цель, где бы цель ни находилась. Положение нод
определяет входная структура.

### Композитная нода

- Композитная нода рисуется как рамка. Заголовок стоит в верхнем левом
  углу рамки.
- Остальное пространство рамки занимают дети и каналы.
- Кликабелен заголовок.

### Раскладка детей

Дети стоят слева направо, в порядке входа:

- Подряд идущие обычные ноды образуют колонку сверху вниз.
- Композитная нода прерывает колонку и занимает отдельную колонку справа.
- Нода после композитной начинает новую колонку справа.

Результат: горизонтальный ряд колонок. Каждая колонка содержит одну
композитную ноду или последовательность обычных нод.

- Колонки выравниваются по верху области детей.
- Правило раскладки позволяет заранее вычислить верхнюю оценку размера
  контейнера. Оценка складывается из:
  - числа колонок обычных нод
  - размеров композитных детей
  - числа связей, которым нужны полосы
  - постоянных внутренних отступов.

### Раскладка корня

Все контейнеры, включая корень, раскладываются по правилу колонок.

В StrictDoc дети корня являются документами, то есть композитными
нодами. Длинный ряд документов плохо читается. Поэтому для корня действует
дополнительное правило:

Правило действует для любых детей корня: композитных и обычных нод.

- Связанные дети корня стоят по правилу колонок, в порядке входа.
- Несвязанные дети корня стоят в отдельном компактном блоке над рядом
  связанных. Ширина блока не больше ширины ряда.
- Ребёнок корня считается связанным, если он или любой его потомок имеет
  связь с нодой вне этого ребёнка.
- Блок несвязанных детей: упаковка по нижнему контуру (skyline), в порядке
  входа. Каждый следующий ребёнок встаёт в самое высокое свободное место,
  где он помещается по ширине блока. При равенстве побеждает самое левое
  место. Ширина блока равна ширине ряда связанных.
- Если ряда связанных нет, блок близок к квадрату. Генератор перебирает
  ширину блока, при которой в верхний ряд встают 1, 2, … n детей подряд, и
  выбирает ширину с отношением ширины упакованного блока к высоте,
  ближайшим к 1. При равенстве побеждает более узкий блок.
- Упаковка блока и правило квадрата заданы в коде каждое в одном месте.
- Правило корня задано в коде в одном месте. Внутренние контейнеры
  раскладываются только по правилу колонок: понятия «несвязанный» внутри
  контейнера нет.

[отложено] Варианты для проверки на реальных данных:

- перенос длинного ряда связанных композитных нод на следующую строку
- вертикальная раскладка ряда
- выбор раскладки опцией.

### Геометрия контейнера

Контейнер снаружи внутрь:

1. Рамка.
2. Заголовок: полоса во всю ширину рамки. Текст заголовка стоит слева и
   по центру полосы по вертикали, до двух строк. Лишнее обрезается, полный текст в
   подсказке.
3. Нижняя линия заголовка: тонкая видимая линия. На ней стоят порты связей
   изнутри (раздел «Связи композитной ноды»). Линия показывает, куда
   приходит такая связь.
4. Область детей с каналами.

Каналы области детей:

| Канал | Где | Ширина |
|---|---|---|
| Верхний коридор | между нижней линией заголовка и верхом колонок | вся ширина области |
| Нижний коридор | между низом самой высокой колонки и нижней гранью рамки | вся ширина области |
| Вертикальный канал | слева от первой колонки, между колонками, справа от последней колонки | высота от верхнего до нижнего коридора |
| Канал колонки | между соседними обычными нодами одной колонки | ширина колонки |

- Колонки разной высоты не выравниваются по низу. Пространство под
  короткой колонкой не является каналом.
- Корень устроен так же, но без рамки и заголовка.
- Между блоком несвязанных детей корня и рядом связанных лежит
  горизонтальный канал.

Размеры:

- Ширина колонки обычных нод: ширина ноды. Ширина колонки композитной
  ноды: ширина этой композитной ноды.
- Высота колонки обычных нод: высоты нод плюс каналы колонки между ними.
- Ширина контейнера: сумма ширин колонок и вертикальных каналов.
- Высота контейнера: заголовок, верхний коридор, самая высокая колонка,
  нижний коридор.
- Размер каждого канала определяет число полос (шаг B). На шаге A у всех
  каналов минимальный размер.

Размеры считаются изнутри наружу (этап 5). Координаты считаются снаружи
внутрь (этап 6).

### Порты обычной ноды

- Порты обычной ноды находятся на верхней и нижней гранях.
- Линия от обычной ноды выходит из порта вертикально. Затем линия
  поворачивает в горизонтальный канал.

### Связи композитной ноды

Точка подключения композитной ноды находится у заголовка. Это правило
действует изнутри и снаружи.

- Снаружи: связь подключается к верхней грани рамки, в её левой части,
  у заголовка. Так связь остаётся видимой рядом с названием контейнера,
  даже если контейнер большой.
- Изнутри: связь с любым потомком подключается к нижней линии заголовка.
  Порты на этой линии стоят слева направо.
- Связь изнутри рисуется в обе стороны: от потомка к заголовку и от
  заголовка к потомку.
- Связь изнутри получает встроенный тип `secondary` (раздел 15).
- Стрелки входят в порты под заголовком по правилу движения в
  горизонтальном канале под заголовком.
- Только связи самой композитной ноды подходят к её заголовку. Проходящие
  связи потомков пересекают рамку через проходные порты.
- Генератор не рисует связь между контейнером и его потомком только на
  основании вложенности. Такая связь рисуется, только если она есть в
  списке связей входа.

### Проходные порты

- Проходные порты находятся только на боковых гранях рамки. Любая связь
  потомка с нодой вне контейнера пересекает рамку через боковую грань.
- Положение проходного порта определяет геометрия линий от детей.
- Линия от проходного порта выходит горизонтально. Затем линия идёт прямо
  к следующей грани контейнера или поворачивает в вертикальный канал.
- В debug-режиме проходные порты видны. Проходные порты позволяют точно
  указать линию с ошибкой.

### Каналы

- Каналы внутри контейнера проходят между всеми детьми.
- Связь проходит по каналам кратчайшим допустимым путём. Внутренняя
  раскладка детей может создавать препятствия, поэтому связь может менять
  координату на каждом уровне вложенности.

### Маршруты

#### Цепочка контейнеров

Общий контейнер связи: самый глубокий контейнер, в котором лежат оба
конца. Корень тоже контейнер.

- Маршрут поднимается от источника через его контейнеры до общего
  контейнера. Каждый контейнер на пути линия покидает через проходной порт
  на боковой грани.
- В общем контейнере маршрут идёт по его каналам.
- Затем маршрут спускается к цели через её контейнеры. В каждый контейнер
  на пути линия входит через проходной порт на боковой грани.
- Связь с предком (раздел «Связи композитной ноды») заканчивается внутри
  предка, на нижней линии его заголовка. Общий контейнер такой связи: сам
  предок.

#### Концы маршрута внутри одного контейнера

| Конец | Откуда выходит линия |
|---|---|
| Порт обычной ноды на верхней грани | в канал над нодой: верхний коридор или канал колонки |
| Порт обычной ноды на нижней грани | в канал под нодой: канал колонки или нижний коридор |
| Порт композитной ноды снаружи (левая часть верхней грани) | в верхний коридор родителя: над колонкой композитной ноды нет других каналов |
| Порт на нижней линии заголовка (связь с предком) | в верхний коридор этого контейнера |
| Проходной порт на грани дочерней композитной ноды | в вертикальный канал рядом с этой гранью |
| Выход через собственную боковую грань | горизонтально через крайний вертикальный канал наружу |

#### Путь по каналам

- Каналы контейнера образуют граф. Горизонтальный канал соединён с
  вертикальным, если они касаются. Коридоры касаются всех вертикальных
  каналов. Канал колонки касается двух вертикальных каналов по бокам своей
  колонки.
- Маршрут внутри контейнера: чередование горизонтальных и вертикальных
  каналов. Каждая смена канала означает поворот.
- Выбор пути: сначала наименьшее число поворотов, затем наименьшая длина.
  Длина оценивается по геометрии с минимальными каналами (шаг A), потому
  что точные размеры каналов ещё не известны. Длина включает вертикальные
  отрезки от граней нод до каналов.
- Грань обычной ноды (верхняя или нижняя) выбирается тем же правилом: из
  двух путей побеждает лучший. При равенстве побеждает верхняя грань.

#### Проходные порты

- Сторона проходного порта (левая или правая грань) выбирается в общем
  контейнере, сверху вниз: сторона, которая даёт лучший путь в общем
  контейнере. Внутри дочернего контейнера линия идёт к выбранной стороне.
- Высота проходного порта следует из маршрута внутри: линия пересекает
  грань на высоте своего последнего горизонтального отрезка внутри
  контейнера, без дополнительного поворота.
- Колонки выровнены по верху. Поэтому высота проходного порта, отсчитанная
  от верха колонок родителя, известна точно, когда контейнер уже посчитан.
- Связь с предком через несколько уровней не имеет отдельного правила.
  Сторона выхода из промежуточных контейнеров выбирается правилом лучшего
  пути. Порт на нижней линии заголовка стоит там, куда линия приходит по
  верхнему коридору.

#### Полосы и порядок расчёта

- Полосы в каждом канале назначаются так же, как в режиме «уровни»: граф
  ограничений, приоритет входа, правостороннее движение, повторное
  использование полос.
- Контейнеры считаются изнутри наружу. Внутри контейнера сначала
  назначаются полосы вертикальных каналов, затем порты граней, затем
  полосы горизонтальных каналов, как в режиме «уровни».
- Порядок концов вдоль вертикального канала берётся по высоте. Высоты
  проходных портов дочерних контейнеров известны точно. Высоты каналов
  колонок оцениваются по геометрии с минимальными каналами. Если после
  расширения каналов порядок изменится, возможно лишнее пересечение, но не
  наложение линий.
- Отрезок, который пересекает грань контейнера, внутри контейнера
  заканчивается на грани без вертикали. Снаружи он продолжается в
  вертикальном канале родителя как вход этого канала.

## 11. Каналы, полосы, порты

### Правостороннее движение

Цель правила: минимум пересечений и визуального шума.

- В горизонтальном канале линии вправо идут в нижней половине, линии
  влево в верхней.
- В вертикальном канале линии вверх идут справа, линии вниз слева.
- Ноду линии обходят по часовой стрелке, как на перекрёстке с
  правосторонним движением.
- Разделительной полосы между направлениями нет.

### Порядок полос при повороте

Две линии входят в канал с одной стороны и поворачивают в одну сторону.
Линия, чей порт ближе к стороне поворота, получает полосу ближе к стороне
входа. Тогда уголки линий вложены друг в друга, и линии не пересекаются.

Пример: линии входят в горизонтальный канал снизу и поворачивают налево.
Самый левый порт получает самую нижнюю полосу левой половины канала.
Следующий порт справа получает полосу выше.

То же правило действует при выходе из канала. Линия, которая выходит
раньше, получает полосу ближе к стороне выхода.

Порядок на входе и порядок на выходе могут противоречить друг другу.
Тогда пересечение неизбежно. Приоритет имеет порядок входа (раздел 8,
«Полосы в канале»).

### Пучки

- Порты одного пучка стоят рядом. Между портами пучка нет портов других
  пучков или встречных связей.
- Полосы одного пучка стоят рядом. Между полосами пучка нет полос других
  источников.
- Линии одного пучка поворачивают вместе, без смены порядка.
- Номер полосы сохраняется на повороте.

### Порты

- Вертикальная связь без смещения использует центральный порт грани.
- Порядок портов и выбор полос подбираются совместно. Цель: минимум
  пересечений или их отсутствие. Порядок зависит от взаимного положения
  источника и цели и от доступного маршрута.
- Входящие и исходящие порты на одной грани стоят в разных позициях
  регулярной сетки. Это следует из правила движения.

### Ширина канала

- Каждая полоса расширяет только свой канал.
- Зазор от крайней полосы горизонтального канала до грани ноды: 12 px.
  Размер канала = шаг полосы × (число полос − 1) + 2 × зазор, но не меньше
  минимального размера канала.
- Последний отрезок связи заканчивается наконечником. Благодаря зазору этот
  отрезок не короче 12 px. Наконечник вписывается в зазор: длина
  наконечника равна зазору минус прямая часть 6 px.
- Вертикальный канал не имеет такого зазора: вдоль боковых граней нод
  наконечников нет. От крайней полосы до ноды остаётся один шаг полосы.
- Раскладка задаёт размеры, стиль наконечника выводится из них. Раскладка
  не зависит от стиля наконечника.
- Полоса, которую освободила закончившаяся связь, используется повторно,
  если это не блокирует другие связи.
- [предложение, низкий приоритет] Единственная линия в канале рисуется в
  базовом зазоре между нодами. Канал расширяется, начиная со второй
  полосы. Правило исключается, если оно усложняет код и тесты.

## 12. Размеры нод и текст

- Ширина ноды фиксирована. Фиксированная ширина даёт ритмичную сетку.
- Высота ноды фиксирована: 3 строки текста.
- Браузер переносит текст внутри `foreignObject`. Строки сверх третьей
  обрезаются. Полный заголовок доступен в подсказке.
- Заголовок обычной ноды выровнен по центру по горизонтали и по
  вертикали.
- Заголовок контейнера выровнен влево и по центру по вертикали.
- Вне браузера текст в `foreignObject` не отображается. Это допустимо в
  первой реализации.
- Отрисовку текста выполняет одна функция. Комментарий в функции
  описывает, что изменить, чтобы текст сохранялся при экспорте SVG.

## 13. Диагностика

- Генератор находит компоненты сильной связности и циклы на уровне
  модели.
- Связи цикла получают встроенный тип `danger` (раздел 15). SVG выделяет
  участников цикла тем же стилем. Каждый цикл получает свой стабильный
  идентификатор. Эталонный кейс галереи: «Two
  cycles have separate diagnostics».
- В режиме «структура» ошибкой считается только цикл.
- Некритичные ошибки генератор показывает значком «!» в треугольнике на
  ноде. При наведении на значок интерактивность показывает текст ошибки.
- Расчёт уровней в режимах «уровни» и «уровни с группами» требует графа
  без циклов. Уровень ноды зависит от уровня её родителя, а в цикле у этой
  зависимости нет начала. Поэтому генератор исключает из расчёта уровней
  по одной связи каждого цикла:
  - генератор перебирает связи в порядке входа
  - связь, которая замкнула бы цикл среди уже принятых связей, не
    участвует в расчёте уровней
  - генератор рисует эту связь как циклическую, наравне с остальными
    связями цикла.

## 14. Debug

- Debug-режим задаётся параметром генератора.
- Debug-слой рисуется поверх графа, полупрозрачным, и не перехватывает
  мышь. Каждый канал показан прямоугольником с короткой подписью (T и B:
  коридоры, V1: вертикальный канал, C2.0: промежуток колонки). Каждая
  полоса показана пунктирной линией в том месте, которое ей даёт
  геометрия.
- Базовые `data-*`-атрибуты есть в SVG всегда: вид элемента,
  идентификатор, источник и цель связи. Базовые атрибуты нужны
  интерактивности.
- В debug-режиме генератор добавляет debug-атрибуты: контейнер, канал,
  полоса, порт. В debug-режиме SVG также содержит проходные порты.
- Вне debug-режима debug-атрибутов нет. Так SVG с тысячами
  нод остаётся меньше.
- Тесты включают debug-режим и читают те же атрибуты. Тестам не нужна
  отдельная debug-структура.
- Debug-JavaScript подключается только на сервере и в галерее. В
  статическом экспорте debug-JavaScript нет.
- Debug-JavaScript работает, только если SVG построен в debug-режиме.
- Option + наведение на элемент (нода, связь, порт, проходной порт)
  показывает таблицу debug-атрибутов элемента.
- Option + клик копирует эти данные.
- Debug-режим включается переключателем: в toolbox на
  сервере, в шапке галереи.

## 15. SVG

- Наконечники стрелок рисуются поверх рамок.
- Зона hover и focus линии шире видимой линии.
- Hover и focus не увеличивают наконечник.
- Размер SVG учитывает линии, наконечники и внешние каналы.

### Сериализация (этап 8)

Сериализатор переводит результат этапов с 1 по 7 в строку SVG. Сериализатор
не меняет геометрию.

Вход:

- результат этапов с 1 по 7
- стили типов связей
- параметр debug-режима
- идентификатор SVG.

Идентификатор SVG ограничивает маркеры наконечников и правила стилей
типов. Поэтому несколько SVG на одной странице не влияют друг на друга.
Каждый SVG на странице получает свой идентификатор.

Детерминированность:

- Ноды идут в порядке входа. Связи идут в порядке `edge-N`.
- Координаты округляются до 0,01 px. Лишние нули не пишутся.

CSS:

- Постоянные стили лежат в отдельном файле рядом с генератором.
- Внутрь SVG сериализатор пишет только то, что зависит от входа: классы
  стилей типов связей и маркеры наконечников для этих стилей.
- Классы именуются по BEM с префиксом `specification-graph-`, например
  `specification-graph-node__box`, `specification-graph-edge--warning`.

Слои снизу вверх:

1. Debug-слой: каналы и полосы. Только в debug-режиме.
2. Ноды: рамка и текст.
3. Связи: видимая линия с наконечником и невидимая широкая зона hover.
   Связи идут после нод, поэтому наконечники лежат поверх рамок.
4. Значки диагностики.

Нода:

- Группа `<g>` с классом ноды и атрибутами:
  - `data-node-id`
  - `data-node-link`, если у ноды есть ссылка
  - `data-node-details`: `details` в JSON, список пар
  - `data-cycle-id`, если нода входит в цикл
  - `data-diagnostics`: тексты диагностики, если есть.
- Рамка `<rect>`.
- Заголовок в `<foreignObject>`: блок HTML с тремя строками и обрезкой
  (раздел 12).
- `<title>` с полным заголовком для подсказки.
- Значок «!» в треугольнике на правом верхнем углу рамки, если у ноды
  есть диагностика. Центр значка стоит на углу, поэтому значок не
  закрывает заголовок. `<title>` значка содержит текст диагностики.
- Сериализатор не пишет `<a>`: ссылку открывает интерактивность по
  Shift + клик (раздел 16).

Связь:

- Группа `<g>` с классом связи и атрибутами:
  - `data-edge-id`
  - `data-source-id`
  - `data-target-id`
  - `data-relation-type`
  - `data-cycle-id`, если связь входит в цикл.
- Класс-модификатор типа связи.
- Видимая линия `<path>` с `marker-end`.
- Зона hover: тот же `<path>`, прозрачный и шире.

### Типы связей и стили

Стиль принадлежит типу связи. У связи один тип, у типа один стиль.

- Модель получает `relation_types: dict[type_id, RelationStyle]`. Стиль
  задаёт подпись для легенды, цвет и рисунок линии.
- Тип связи без стиля во входе получает стиль `default`.
- Генератор знает несколько встроенных типов. У каждого есть стиль по
  умолчанию. Вход может заменить стиль встроенного типа.

| Встроенный тип | Стиль по умолчанию | Значение | Ситуация в генераторе |
|---|---|---|---|
| `default` | чёрная сплошная линия | обычная связь | связь без своего типа |
| `secondary` | серая сплошная линия | вспомогательная связь, может указывать куда угодно | тип из входа (например, ссылка в тексте); связь изнутри контейнера (раздел 10) |
| `warning` | пунктир | предупреждение | связь через уровень в режимах «уровни» и «уровни с группами» |
| `danger` | красная линия | сильнее предупреждения, но не ошибка входа | связь цикла |

- Тип шире ситуации. Например, адаптер может передать тип `secondary`
  для любой связи.
- Ситуация генератора заменяет тип связи из входа своим встроенным типом.
- Если связь попадает в несколько ситуаций, побеждает более сильный тип:
  `danger`, затем `warning`, затем тип из входа.

Debug-режим:

- Связь получает `data-debug-lanes` (например `H0:1 V2:0 H1:0`) и
  `data-debug-ports` (грань и слот источника и цели).
- Debug-слой рисует прямоугольники каналов.

## 16. Интерактивность

- Панорамирование: мышь с зажатым пробелом.
- Масштаб: колесо мыши. Команды `+`, `−`, сброс, «вписать».
- Показ текущего масштаба в процентах.
- При загрузке масштаб 100%, если схема помещается. Иначе схема
  вписывается.
- Панель информации и легенда являются отдельным HTML-блоком. Блок не
  двигается вместе с полотном.
- Shift + наведение на ноду показывает таблицу с данными ноды.
- Shift + клик открывает ссылку ноды в новой вкладке.
- Shift + Enter на ноде в фокусе открывает ссылку ноды в новой вкладке.
- Простой клик и выделение текста не открывают ссылку.
- После трансформаций работают hover, focus, навигация с клавиатуры и
  ссылки.

## 17. Экспорт SVG-файла

- Страница на сервере предлагает сохранить SVG как файл.
- Статический экспорт кладёт SVG-файл в папку экспорта. Страница содержит
  ссылку на этот файл.
- SVG-файл содержит легенду.
- SVG-файл не содержит интерактивности.

## 18. Галерея

- Галерея строится скриптом в статическую HTML-страницу.
- Для каждого кейса галерея показывает название, описание, входное
  дерево и связи, SVG.
- Каждый кейс галереи является также тестовым входом.
- Галерея не заменяет тесты.
- Галерея покрывает основные кейсы каждого режима.
- Пока маршруты режима «структура» не реализованы, галерея показывает
  раскладку этого режима без связей. Подпись под картинкой говорит об
  этом.
- Галерея показывает результат генератора с параметрами по умолчанию.
- Если правило выбрано из нескольких вариантов, кейс может показать
  рядом отвергнутый вариант. Картинка отвергнутого варианта помечена как
  отвергнутая. Подпись называет значение параметра генератора, которое
  строит этот вариант. Генератор без этого параметра так не строит.
